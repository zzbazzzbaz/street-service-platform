# 8.12 服务阵地接口需求

更新时间：2026-08-11  
适用范围：用户端微信小程序、街道管理后台 H5

## 1. 业务调整

“服务阵地”不再从志愿任务或线下活动中提取地点。它是社区的常驻服务点，独立维护、独立启停，不随活动开始或结束变化。

每条服务阵地需要维护：

- 服务阵地名称
- 具体地址
- 开放时间
- 服务事项
- 纬度和经度，用于小程序调用 `wx.openLocation` 导航
- 启用状态

请新增独立的服务阵地数据模型和接口，不要继续复用 `/activities` 的 `location` 字段。

## 2. 数据字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | integer | 响应 | 服务阵地 ID |
| `name` | string | 是 | 服务阵地名称，最长 100 个字符 |
| `address` | string | 是 | 居民实际到达时使用的完整地址，最长 200 个字符 |
| `business_hours` | string | 是 | 开放时间，最长 100 个字符，例如 `周一至周五 09:00-17:00` |
| `service_content` | string | 是 | 服务事项，最长 500 个字符 |
| `latitude` | number | 是 | 纬度，范围 `-90` 至 `90` |
| `longitude` | number | 是 | 经度，范围 `-180` 至 `180` |
| `is_active` | boolean | 是 | 是否在小程序展示 |
| `created_at` | datetime | 响应 | 创建时间 |
| `updated_at` | datetime | 响应 | 更新时间 |

经纬度必须成对保存，不能只填写其中一个。后台新增和编辑时会要求完整坐标，因为小程序的导航功能需要同时使用两个坐标。

## 3. 用户端接口

### 3.1 查询服务阵地

```http
GET /api/service-locations?page=1&page_size=50
```

接口要求：

- 允许未登录访问，不校验用户 Token。
- 只返回 `is_active=true` 的服务阵地。
- 默认按后台维护时间倒序，或按后端确定的稳定顺序返回；分页字段必须准确。
- 没有数据时返回成功和空数组，不返回 404。
- 不能返回已停用的服务阵地。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [
      {
        "id": 1,
        "name": "东里社区便民服务站",
        "address": "北京市东城区东里社区服务楼一层",
        "business_hours": "周一至周五 09:00-17:00",
        "service_content": "政策咨询、老年人服务、便民证明办理",
        "latitude": 39.908823,
        "longitude": 116.39747,
        "is_active": true,
        "created_at": "2026-08-11T10:00:00+08:00",
        "updated_at": "2026-08-11T10:00:00+08:00"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 50
  }
}
```

## 4. 街道管理后台接口

后台接口均需要管理员 Bearer Token。

### 4.1 查询列表

```http
GET /api/admin/service-locations?page=1&page_size=100&keyword=...&is_active=true|false
```

要求：

- `keyword` 可匹配服务阵地名称、地址和服务事项。
- `is_active` 为可选筛选参数。
- 筛选在分页前执行，`total` 返回筛选后的真实总数。
- 返回第 2 节中的全部字段。

### 4.2 新增

```http
POST /api/admin/service-locations
```

请求示例：

```json
{
  "name": "东里社区便民服务站",
  "address": "北京市东城区东里社区服务楼一层",
  "business_hours": "周一至周五 09:00-17:00",
  "service_content": "政策咨询、老年人服务、便民证明办理",
  "latitude": 39.908823,
  "longitude": 116.39747,
  "is_active": true
}
```

### 4.3 编辑

```http
PATCH /api/admin/service-locations/{location_id}
```

请求字段与新增接口一致。前端会提交完整对象，后端应支持完整更新名称、地址、开放时间、服务事项、经纬度和启用状态。

### 4.4 启停服务阵地

```http
POST /api/admin/service-locations/{location_id}/status
```

请求：

```json
{
  "is_active": false
}
```

停用后，用户端查询接口必须立即不再返回该服务阵地；重新启用后恢复展示。

## 5. 错误校验

以下情况返回 HTTP 400，并返回明确中文错误信息：

- 名称或具体地址为空。
- 开放时间或服务事项超出长度限制。
- 只填写纬度或只填写经度。
- 经纬度不是有效数字或超出合法范围。
- 服务阵地 ID 不存在时编辑或启停。

## 6. 联调验收

1. 小程序“服务阵地”页面不再请求活动接口，也不显示活动地点。
2. 用户未登录时也可以查看启用中的服务阵地。
3. 每条卡片展示名称、地址、开放时间和服务事项。
4. 点击导航时使用返回的 `latitude`、`longitude` 调用 `wx.openLocation`。
5. 后台可以新增、编辑、启用和停用服务阵地，并维护坐标。
6. 后台停用后，小程序刷新页面不再展示该服务阵地。

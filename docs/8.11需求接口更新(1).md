# 8.11 需求接口更新

更新时间：2026-08-11  
适用范围：用户端微信小程序、街道管理后台 H5  
对接主题：学习公告、置顶公告、学习图文富文本编辑

## 1. 本次后端工作范围

本次前端新增了以下业务能力，后端需要补充或确认对应接口：

1. 学习内容可以标记为“公告类型”。
2. 后台可以筛选公告，并从已上架公告中选择最多 3 条置顶公告及调整展示顺序。
3. 小程序首页和“知识学习”页需要读取置顶公告。
4. 图文学习内容改为富文本编辑，正文中可以直接上传并插入图片。

页面名称、卡片布局和编辑器工具栏属于纯前端调整，不需要新增接口。

## 2. 学习内容字段更新

请在学习内容模型中增加以下字段，并在用户端、后台端的学习内容列表和详情响应中统一返回：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `is_announcement` | boolean | `false` | 是否为公告类型 |
| `is_pinned` | boolean | `false` | 是否为置顶公告 |
| `pin_order` | integer/null | `null` | 置顶展示顺序，从 `1` 开始 |

现有 `created_at` 字段也必须返回，用于普通内容按发布时间倒序排列。

业务约束：

- 公告统一使用 `content_type=article`。
- 只有 `is_announcement=true`、`is_active=true` 且有封面的内容可以置顶。
- 全系统最多同时存在 3 条置顶公告。
- 置顶顺序必须从 `1` 开始连续排列，不能重复或跳号。
- 内容取消上架或由公告改为普通学习内容时，后端必须同步设置 `is_pinned=false`、`pin_order=null`。
- 普通学习内容不能设置为置顶公告。

## 3. 用户端接口更新

### 3.1 学习内容列表

```http
GET /api/learning/contents?page=1&page_size=20&is_announcement=true|false&is_pinned=true|false
```

调整要求：

- `is_announcement`、`is_pinned` 为可选筛选参数。
- 不传筛选参数时，继续返回全部已上架的公告和普通学习内容。
- 筛选应在数据库分页前完成，`total` 必须为筛选后的真实数量。
- 每项返回 `is_announcement`、`is_pinned`、`pin_order`、`created_at`。
- 默认按照 `created_at` 倒序返回，不能因为置顶状态改变普通列表分页顺序。

### 3.2 学习内容详情

```http
GET /api/learning/contents/{content_id}
```

详情响应需同步返回新增字段，并完整返回富文本 `body`。公告复用现有学习详情、计时完成和积分发放逻辑，不另外建立一套详情或积分接口。

### 3.3 获取首页置顶公告

```http
GET /api/learning/announcements/pinned
```

用途：小程序首页和“知识学习”页读取当前有效的置顶公告。

要求：

- 允许未登录访问，不校验用户 Token。
- 只返回 `is_active=true`、`is_announcement=true`、`is_pinned=true` 的内容。
- 最多返回 3 条，严格按照 `pin_order` 升序排列。
- 没有置顶公告时返回成功和空数组，不能返回 404。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": 12,
      "title": "社区交通安全提示",
      "cover_url": "https://commu.iloveminmeng.com/media/learning/notice.jpg",
      "body": "<p>公告正文</p>",
      "content_type": "article",
      "image_urls": [],
      "video_url": null,
      "points": 10,
      "required_seconds": 30,
      "is_active": true,
      "is_announcement": true,
      "is_pinned": true,
      "pin_order": 1,
      "created_at": "2026-08-11T10:00:00+08:00"
    }
  ]
}
```

## 4. 街道管理后台接口更新

### 4.1 后台学习内容列表

```http
GET /api/admin/learning/contents?page=1&page_size=50&keyword=...&is_announcement=true|false&is_active=true|false
```

调整要求：

- 支持 `is_announcement`、`is_active` 可选筛选。
- 筛选后再分页，并返回准确的 `total`。
- 每项返回第 2 节列出的新增字段和 `created_at`。

### 4.2 新建和编辑学习内容

```http
POST /api/admin/learning/contents
PATCH /api/admin/learning/contents/{content_id}
```

前端当前提交格式：

```json
{
  "title": "社区交通安全提示",
  "is_announcement": true,
  "content_type": "article",
  "body": "<h2>安全提示</h2><p>正文内容</p><p><img src=\"https://commu.iloveminmeng.com/media/learning/example.jpg\" alt=\"现场图片\"></p>",
  "cover": "https://commu.iloveminmeng.com/media/learning/cover.jpg",
  "image": "",
  "video": "",
  "points": 10,
  "required_seconds": 30,
  "is_active": true
}
```

后端处理要求：

- 接收并保存 `is_announcement`。
- 公告类型必须校验为 `content_type=article`。
- `body` 使用长文本字段完整保存 HTML，不能转义成普通文本、截断或删除合法的正文图片。
- 编辑接口必须允许完整替换 `body`，再次查询时应原样返回可渲染的 HTML。
- 请求继续兼容现有 `cover`、`image`、`video` 字段；响应统一返回现有前端可读取的 `cover_url`、`image_urls`、`video_url`。
- 下架公告或取消公告属性时，自动清除其置顶状态和顺序。

### 4.3 批量保存置顶公告

```http
POST /api/admin/learning/announcements/pinned
```

该接口为全量覆盖保存，而不是增量追加。

请求示例：

```json
{
  "items": [
    { "content_id": 12, "pin_order": 1 },
    { "content_id": 8, "pin_order": 2 },
    { "content_id": 19, "pin_order": 3 }
  ]
}
```

接口规则：

- `items` 最多 3 条，内容 ID 和 `pin_order` 均不能重复。
- `items` 可以为空数组，表示取消全部置顶公告。
- 请求中未出现的原置顶公告应取消置顶并清空 `pin_order`。
- 每项内容必须存在、已上架、属于公告类型且已配置封面。
- 所有变更必须在同一数据库事务内完成，任一项失败时整体回滚。
- 校验失败返回 HTTP 400 和明确错误信息。
- 成功后返回更新后的置顶公告数组，并按 `pin_order` 升序排列。

## 5. 富文本图片上传接口确认

富文本编辑器复用现有后台图片上传接口，不要求另建上传接口，但该接口需要满足以下约定：

```http
POST /api/admin/uploads/images
Content-Type: multipart/form-data
Authorization: Bearer <admin_access_token>
```

表单字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `files` | file，可重复 | 本次上传的图片文件 |
| `business_type` | string | 固定传 `learning_content` |
| `related_id` | integer，可选 | 编辑已有内容时传学习内容 ID；新增内容时可能为空 |

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "files": [
      {
        "file_id": "abc123",
        "url": "https://commu.iloveminmeng.com/media/learning/example.jpg",
        "original_name": "example.jpg",
        "size": 102400,
        "mime_type": "image/jpeg",
        "created_at": "2026-08-11T10:00:00+08:00"
      }
    ]
  }
}
```

上传要求：

- `data.files` 必须为数组，每项必须有可直接使用的 `url`。
- 支持 JPEG、PNG、WebP，单张最大 10 MB。
- 新增学习内容尚无 `related_id` 时也必须允许上传，不能因此报错。
- 返回地址必须为微信真机可访问的 HTTPS 地址，响应头 `Content-Type` 必须与实际图片类型一致。
- 图片域名需要加入微信小程序的 downloadFile 合法域名，不能返回仅内网可访问、HTTP、临时签名失效或需要后台登录态的地址。

## 6. 富文本安全与兼容要求

后端如执行 HTML 清洗，应至少保留学习正文会使用的常见标签和属性：

- 标签：`p`、`br`、`h1` 至 `h5`、`strong`、`em`、`u`、`s`、`blockquote`、`ul`、`ol`、`li`、`a`、`img`、`table`、`thead`、`tbody`、`tr`、`th`、`td`、`pre`、`code`。
- 常用属性：`src`、`alt`、`href`、`target`、`style`、`width`、`height`、`colspan`、`rowspan`。

同时必须移除 `script`、事件属性（如 `onclick`）和危险协议。允许的图片地址仅限 HTTPS 或系统自身可转换的媒体相对路径。

## 7. 验收清单

1. 后台可以新建、编辑和筛选公告图文内容。
2. 富文本正文保存后重新打开编辑窗口，文字格式、表格、链接和正文图片仍然存在。
3. 后台可以选择 0 至 3 条置顶公告并调整顺序，刷新后结果保持一致。
4. 小程序未登录时可以读取置顶公告；没有数据时正常显示空状态，不报 404。
5. 小程序首页最多展示 3 条置顶公告，“知识学习”页按同一顺序展示置顶公告。
6. 非置顶公告和普通学习内容在下方按 `created_at` 倒序混合展示。
7. 公告下架或取消公告属性后，下一次请求不再出现在置顶列表中。
8. 后台上传的封面和正文图片可在微信开发者工具、真机调试和体验版中正常加载。
9. 公告学习完成继续复用现有完成接口，只产生一次学习记录和一次积分发放。

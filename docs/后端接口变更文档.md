# 后端接口变更文档

更新时间：2026-06-28

## 1. 变更概述

本次后端将原“商户商品兑换 / 积分商城”流程调整为“商户固定码积分支付”流程。

核心变化：

- 删除商户商品、商品兑换记录、商户确认交付等旧商城能力。
- 新增后台积分兑元比例配置。
- 用户扫商户固定码后，直接使用积分向商户支付。
- 系统不记录商品、订单或商户商品流水，只记录积分流水。
- 商户端通过积分流水查看本商户收到的积分支付记录。

## 2. 已删除接口

以下接口已删除，不再兼容：

| 方法 | 路径 | 原用途 |
| --- | --- | --- |
| `GET` | `/api/merchant-products` | 商品列表 |
| `GET` | `/api/merchant-products/{product_id}` | 商品详情 |
| `POST` | `/api/merchant-products/{product_id}/redeem` | 商品兑换 |
| `GET` | `/api/product-redemptions` | 用户商品兑换记录 |
| `GET` | `/api/merchant/redemptions` | 商户商品兑换记录 |
| `POST` | `/api/merchant/redemptions/{redemption_id}/complete` | 商户确认交付 |
| `GET` | `/api/merchant/redemptions/summary` | 商户月度兑换汇总 |

前端如果仍调用这些接口，会收到 `404`。

## 3. 新增接口

### 3.1 商户固定码

`GET /api/merchant/fixed-code`

认证：商户 token。

用途：商户端获取固定码内容，前端据此生成二维码。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "merchant_id": 1,
    "merchant_name": "便民超市",
    "code_content": "street-service://merchant-pay?merchant_id=1"
  }
}
```

### 3.2 商户支付信息

`GET /api/merchants/{merchant_id}/payment-info`

认证：用户 token。

用途：用户扫码后展示商户名称、当前兑换比例和用户积分余额。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "merchant_id": 1,
    "merchant_name": "便民超市",
    "phone": "13900000000",
    "address": "幸福街道便民服务点",
    "points_per_yuan": 100,
    "balance": 120
  }
}
```

### 3.3 商户积分支付

`POST /api/merchants/{merchant_id}/point-payments`

认证：用户 token。

请求体：

```json
{
  "points": 100,
  "request_no": "client-request-id"
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `points` | integer | 是 | 本次要抵扣的积分 |
| `request_no` | string | 否 | 前端请求号；同一商户同一请求号幂等 |

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 12,
    "merchant_id": 1,
    "merchant_name": "便民超市",
    "points": 100,
    "yuan_amount": "1.00",
    "balance_after": 20,
    "request_no": "client-request-id",
    "created_at": "2026-06-28T10:00:00+08:00"
  }
}
```

业务规则：

- 商户必须启用。
- `points` 必须大于 0。
- 用户积分余额必须足够。
- 后台必须存在启用的积分兑换比例。
- `request_no` 非空时，同一商户重复提交同一 `request_no` 返回原积分流水，不重复扣分。

### 3.4 商户积分支付流水

`GET /api/merchant/point-records`

认证：商户 token。

用途：商户查看本商户收到的积分支付流水。

查询参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | integer | 否 | 页码 |
| `page_size` | integer | 否 | 每页数量 |

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [
      {
        "id": 12,
        "merchant_id": 1,
        "merchant_name": "便民超市",
        "member_id": 3,
        "member_name_masked": "张*",
        "member_phone_masked": "138****0000",
        "points": 100,
        "yuan_amount": "1.00",
        "balance_after": 20,
        "request_no": "client-request-id",
        "created_at": "2026-06-28T10:00:00+08:00"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20
  }
}
```

## 4. 变更接口

### 4.1 积分明细

`GET /api/points/records`

积分流水新增商户支付相关字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `merchant_id` | integer/null | 商户积分支付对应的商户 ID |
| `merchant_name` | string | 商户名称；非商户支付流水为空字符串 |
| `yuan_amount` | string/null | 商户积分支付折算金额 |
| `request_no` | string | 商户积分支付请求号 |

`source_type` 新增：

- `merchant_payment`：商户积分支付。

## 5. 前端改造建议

用户端流程：

1. 扫描商户固定码，解析 `merchant_id`。
2. 调用 `GET /api/merchants/{merchant_id}/payment-info` 展示商户、兑换比例和用户余额。
3. 用户输入抵扣积分。
4. 调用 `POST /api/merchants/{merchant_id}/point-payments`。
5. 支付成功页展示商户名称、扣减积分、折算金额、支付时间和流水 ID，供商户核验。

商户端流程：

1. 登录后调用 `GET /api/merchant/fixed-code` 获取固定码内容。
2. 前端生成并展示固定二维码。
3. 调用 `GET /api/merchant/point-records` 查看本商户积分支付流水。

## 6. 后台配置

后台新增“积分兑换比例”配置入口。

当前规则：

- `points_per_yuan = 100` 表示 100 积分抵 1 元。
- 支付时会把折算金额固化到积分流水的 `yuan_amount` 字段。
- 后续修改兑换比例不会影响历史流水。

# 部署文档

- 项目：街道服务数字化操作系统
- 版本：v1.0
- 更新时间：2026-08-25
- 代码仓库：https://git.gqt.plus/gqt/street-service-digitalization.git

## 1. 部署架构

生产环境采用 Docker Compose 单机部署，三个容器：

```text
┌─────────────────────────────────────────┐
│  Docker Compose                          │
│  ┌───────┐  ┌───────┐  ┌─────────────┐  │
│  │ db    │  │ redis │  │ web         │  │
│  │ PG 17 │  │ 7.4   │  │ gunicorn    │  │
│  │ :5432 │  │ :6379 │  │ :8000       │  │
│  └───────┘  └───────┘  └─────────────┘  │
└─────────────────────────────────────────┘
        ▲
   Nginx / 反向代理（HTTPS + 域名）
```

Web 容器内运行 Gunicorn（3 workers），静态文件由 WhiteNoise 托管；媒体文件存储在 Web 容器文件系统 `data/media/`。

## 2. 环境要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Linux（建议 Ubuntu 22.04+）/ macOS（本地开发） |
| Docker | 20.10+（含 docker compose 插件） |
| 服务器配置 | 2 核 4G 以上（业务量小，可更低） |
| 域名 | 一个，指向服务器公网 IP（如 `8000.frp.chatgqt.top`） |
| 代理 | Nginx 或 frp（已有 frp 域名可直用） |

## 3. 获取代码

## 4. 本地开发部署

### 4.1 初始化（uv 环境）

```bash
cd backend
uv sync                       # 安装依赖（Python 3.12）
cp .env.example .env          # 复制环境变量
```

### 4.2 启动依赖服务（PostgreSQL / Redis）

方式一：Docker 只跑依赖

```bash
cd backend
docker compose up -d db redis
```

方式二：本机安装 PostgreSQL 17 / Redis 7 并创建数据库：

```bash
# PostgreSQL
CREATE DATABASE street OWNER street;
CREATE USER street WITH PASSWORD 'street';
```

`.env` 中数据库连接默认即 `127.0.0.1:5432 / street / street`。

### 4.3 初始化数据库与数据

```bash
uv run python manage.py migrate
uv run python manage.py seed_mvp   # 生成联调测试数据
```

### 4.4 启动服务

```bash
uv run python manage.py runserver 0.0.0.0:8000
```

访问入口：

| 入口 | 地址 |
| --- | --- |
| API 文档（Swagger） | http://127.0.0.1:8000/api/docs |
| OpenAPI JSON | http://127.0.0.1:8000/api/openapi.json |
| 健康检查 | http://127.0.0.1:8000/api/health |
| Django Admin | http://127.0.0.1:8000/admin/ |

seed 后默认账号：`admin / admin123456`（后台）、用户 openid `test-openid`、商户 openid `merchant-openid`。

### 4.5 本地测试

```bash
uv run python manage.py test -v 2
```

## 5. Docker 生产部署

### 5.1 配置环境变量

在 `backend/` 下创建 `.env`（或直接 export）：

```bash
cd backend
cp .env.example .env
```

生产关键项：

```env
DJANGO_SECRET_KEY=生产环境生成随机串（openssl rand -hex 32）
DJANGO_DEBUG=false
DJANGO_ALLOWED_HOSTS=8000.frp.chatgqt.top,your-domain.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://8000.frp.chatgqt.top,https://your-domain.com

# PostgreSQL（Docker 内连接 db 容器）
DJANGO_DB_NAME=street
DJANGO_DB_USER=street
DJANGO_DB_PASSWORD=更换强密码（同时修改 docker-compose.yml 中 db 的 POSTGRES_PASSWORD）
DJANGO_DB_HOST=db
DJANGO_DB_PORT=5432

# Redis
DJANGO_REDIS_URL=redis://redis:6379/0

# Token
ACCESS_TOKEN_SECRET=与 SECRET_KEY 不同的一串随机数
ACCESS_TOKEN_EXPIRES_SECONDS=7200

# 微信小程序（如需正式微信登录）
WECHAT_MINIAPP_APPID=wx...
WECHAT_MINIAPP_SECRET=...
```

> 注意：`docker-compose.yml` 中 web 服务的环境变量为硬编码默认值，其中 `DJANGO_DB_PASSWORD: street`、`DJANGO_ALLOWED_HOSTS: "*"`、`DJANGO_DEBUG: "false"`。生产部署前请修改 compose 文件，或改为 `${DJANGO_DB_PASSWORD:-street}` 形式从 `.env` 注入。

### 5.2 构建并启动

```bash
cd backend
docker compose up -d --build
```

首次启动会自动执行健康检查（db/redis），web 依赖健康后启动。

### 5.3 初始化生产数据库

首次部署需执行迁移（在 web 容器内）：

```bash
docker compose exec web uv run python manage.py migrate
docker compose exec web uv run python manage.py createsuperuser   # 创建后台超级管理员
```

`collectstatic` 已在 Dockerfile 构建阶段执行，无需手动运行。

> 注意：**不要**在生产执行 `seed_mvp`（仅开发联调用）。

### 5.4 验证

```bash
docker compose ps              # 三个服务均为 healthy/running
curl http://127.0.0.1:8000/api/health
# {"code":0,"message":"success","data":{"status":"ok"}}
```

## 6. 域名与 HTTPS

### 6.1 Nginx 反向代理（推荐）

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate     /etc/nginx/ssl/your-domain.com.pem;
    ssl_certificate_key /etc/nginx/ssl/your-domain.com.key;

    client_max_body_size 20m;   # 媒体上传，按需调整

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /media/ {
        # 若媒体文件在 web 容器内，用代理访问；建议挂载卷后直接用文件路径
        proxy_pass http://127.0.0.1:8000;
    }
}

server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

### 6.2 frp 内网穿透（开发/演示期）

本项目演示环境使用 frp 域名 `8000.frp.chatgqt.top`，需在：

- `.env` 的 `DJANGO_ALLOWED_HOSTS` 与 `DJANGO_CSRF_TRUSTED_ORIGINS` 中包含该域名；
- frp 配置中将远程端口映射到服务器 `127.0.0.1:8000`。

## 7. 数据备份与恢复

### 7.1 数据库备份

```bash
# 手动备份（crontab 每日执行）
docker compose exec -T db pg_dump -U street street > backup_$(date +%Y%m%d).sql

# 定时任务示例（每天凌晨 3 点，保留 14 天）
0 3 * * * cd /opt/street && docker compose exec -T db pg_dump -U street street | gzip > backups/street_$(date +\%Y\%m\%d).sql.gz && find backups -mtime +14 -delete
```

### 7.2 恢复

```bash
cat backup.sql | docker compose exec -T db psql -U street street
```

### 7.3 媒体文件备份

```bash
docker cp <web容器ID>:/app/data/media ./media_backup
```

```bash
# 查看日志
docker compose logs -f web
docker compose logs -f db redis

# 进入容器
docker compose exec web bash

# 重启单个服务

# 停止 / 清理
```

## 10. 常见问题

| 问题 | 处理 |
| --- | --- |
| `Access denied` / 数据库连不上 | 检查 `.env` 数据库密码与 compose 中 `POSTGRES_PASSWORD` 是否一致 |
| 403 Forbidden（后台页面） | 确认 `DJANGO_CSRF_TRUSTED_ORIGINS` 包含当前域名 |
| 400 Bad Request: Invalid HTTP_HOST | `DJANGO_ALLOWED_HOSTS` 未包含请求域名 |
| 上传图片后 URL 为 http | 反代需传 `X-Forwarded-Proto: https`（settings 已配置 `SECURE_PROXY_SSL_HEADER`） |
| 接口频繁报 `42900` | 触发限流（登录 5/分钟/IP、支付 20/分钟/用户），正常等待即可；临时排查可设 `RATELIMIT_ENABLE=false`（仅测试环境） |
| 支付提示"今日已达上限" | 单用户单商户每日限 2 次，为业务规则（`DAILY_MERCHANT_PAYMENT_LIMIT`），次日恢复 |
| 静态资源 404 | 确认构建时已执行 `collectstatic`（Dockerfile 已包含） |

## 11. 安全基线

1. 生产环境必须修改 `DJANGO_SECRET_KEY` / `ACCESS_TOKEN_SECRET` 与数据库密码，禁止使用 `dev-only-change-me` / `street` 默认值。
2. `DJANGO_DEBUG` 必须为 `false`。
3. 数据库端口（5432）不应直接暴露公网，仅限内网/容器网络。
4. 媒体上传建议限制大小与类型（Nginx `client_max_body_size` + 后端校验）。

## 2. CI/CD 流程

### CI 工作流

文件：`.gitea/workflows/backend-docker.yml`

- **触发条件**：push 到 `main` 分支且 `backend/` 目录有变更，或手动触发
- **构建**：使用 `backend/Dockerfile` 构建 Docker 镜像
- **推送**：打两个 tag 推送到 Gitea Container Registry
  - `git.gqt.plus/gqt/street-service-digitalization-backend:{commit_sha}`
  - `git.gqt.plus/gqt/street-service-digitalization-backend:latest`
- **PR 事件**：只构建不推送（验证 Dockerfile 是否可正常构建）

## 5. 配置文件

### docker-compose.yml

部署在服务器 `~/street-service-digitalization/docker-compose.yml`，核心配置：

- **db**：PostgreSQL 17.10-alpine，数据持久化到 Docker named volume `pg_data`，内存限制 512 MB
- **redis**：Redis 7.4-alpine，数据持久化到 Docker named volume `redis_data`，内存限制 128 MB
- **web**：从 Gitea Container Registry 拉取镜像，端口映射 `127.0.0.1:18002:8000`，内存限制 768 MB，媒体目录挂载到 `./media`
- 数据库和 Redis 仅在 Docker 内部网络通信，不暴露端口到宿主机

### .env 文件

部署在服务器 `~/street-service-digitalization/.env`，包含以下变量：

```env
DJANGO_SECRET_KEY=<密钥>
WECHAT_MINIAPP_APPID=<微信小程序 AppID>
WECHAT_MINIAPP_SECRET=<微信小程序 Secret>
```

> 其余环境变量（数据库连接、Redis、调试模式等）直接写在 docker-compose.yml 中。

### Nginx 配置

Nginx 配置直接写在 `/etc/nginx/nginx.conf` 中（由 Certbot 自动管理 SSL 部分）：

- **80 端口**：HTTP → HTTPS 301 重定向（Certbot 自动添加）
- **443 端口**：SSL 终止，反代到 `127.0.0.1:18002`
- **/media/**：直接从文件系统 `~/street-service-digitalization/media/` 提供静态文件服务
- **client_max_body_size**：20 MB（允许图片上传）

### SSL 证书

- 证书路径：`/etc/letsencrypt/live/commu.iloveminmeng.com/`
- 自动续签：Certbot 已配置 systemd timer，无需手动干预
- 手动续签测试：`sudo certbot renew --dry-run`

## 7. 故障排查

### 图片无法访问（403）

**原因**：`/home/andrew` 目录权限为 `750`，Nginx 的 `www-data` 用户无法进入。

**解决**：

```bash
sudo chmod 755 /home/andrew
```

### 容器启动失败

检查日志：

```bash
docker compose logs web
```

常见原因：
- 数据库未就绪：`depends_on` 配置了 healthcheck，等待即可
- 镜像拉取失败：检查 `docker login git.gqt.plus` 是否成功
- 端口冲突：检查 `127.0.0.1:18002` 是否被占用：`sudo ss -tlnp | grep 18002`

### SSL 证书过期

证书自动续签，如需手动检查：

```bash
sudo certbot certificates                    # 查看证书状态
sudo certbot renew --dry-run                 # 测试续签
sudo systemctl reload nginx                  # 续签后重载 Nginx
```

### 数据库连接失败

```bash
# 检查 PostgreSQL 容器状态
docker compose ps db

# 进入数据库
docker compose exec db psql -U street -d street

# 检查数据库大小
docker compose exec db psql -U street -d street -c "SELECT pg_size_pretty(pg_database_size('street'));"
```

### Redis 连接失败

```bash
docker compose ps redis
docker compose exec redis redis-cli ping
```

## 9. 端口分配

| 端口 | 用途 | 访问范围 |
|------|------|----------|
| 80 | Nginx HTTP（重定向到 HTTPS） | 公网 |
| 443 | Nginx HTTPS | 公网 |
| 18002 | 后端 gunicorn | 仅本机 127.0.0.1 |
| 5432 (容器内) | PostgreSQL | 仅 Docker 网络 |
| 6379 (容器内) | Redis | 仅 Docker 网络 |

> 端口 8000 被服务器上其他服务占用，本服务使用 18002。

## 10. 从零部署（参考）

如需在新服务器上部署，按以下步骤操作：

1. **安装 Docker 和 Docker Compose**

   ```bash
   sudo apt update
   sudo apt install -y docker.io docker-compose-v2
   sudo usermod -aG docker $USER
   # 重新登录使 docker 组生效
   ```

2. **安装 Nginx 和 Certbot**

   ```bash
   sudo apt install -y nginx python3-certbot-nginx
   ```

3. **创建部署目录**

   ```bash
   mkdir -p ~/street-service-digitalization/media
   ```

4. **创建 docker-compose.yml 和 .env**

   参考本仓库的 `backend/docker-compose.yml`，将 `build: .` 改为 `image: git.gqt.plus/gqt/street-service-digitalization-backend:latest`，并添加内存限制和端口映射。

5. **登录 Gitea Container Registry 并拉取镜像**

   ```bash
   echo "<TOKEN>" | docker login git.gqt.plus -u gqt --password-stdin
   docker pull git.gqt.plus/gqt/street-service-digitalization-backend:latest
   ```

6. **启动服务**

   ```bash
   cd ~/street-service-digitalization
   docker compose up -d
   ```

7. **执行迁移和生成测试数据**

   ```bash
   docker compose exec -T web uv run python manage.py migrate
   docker compose exec -T web uv run python manage.py seed_mvp
   ```

8. **配置 Nginx 反向代理**

   在 `/etc/nginx/nginx.conf` 的 `http` 块内添加：

   ```nginx
   server {
       listen 80;
       server_name <域名>;

       client_max_body_size 20M;

       location /media/ {
           alias /home/<用户>/street-service-digitalization/media/;
       }

       location / {
           proxy_pass http://127.0.0.1:18002;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```

   ```bash
   sudo nginx -t
   sudo systemctl reload nginx
   ```

9. **申请 SSL 证书**

   ```bash
   sudo certbot --nginx -d <域名> --non-interactive --agree-tos --email <邮箱> --redirect
   ```

10. **修复目录权限**

    ```bash
    sudo chmod 755 /home/<用户>
    ```

11. **验证**

    ```bash
    curl https://<域名>/api/health
    ```
